# 桌面任务租约

## 配置与使用

默认 `ODSH_LEASE_MODE=off`，兼容现有行为，不加锁。宿主启动前设置 `ODSH_LEASE_MODE=single-process`，强制实际运行时和旧 CUA/视觉入口携带凭证；其他非空值 fail-closed。不要在任务中切换模式。这是**单 Node 进程部署声明**，不是分布式锁，不读取插件配置键。

1. 调用 `odsh.lease`：`{"action":"acquire","owner":"任务标签","ttlMs":30000}`。返回随机 `token`、标签、固定资源 `desktop`、时长和仅供展示的墙钟 `expiresAt`；内部使用单调时钟。
2. 整个多步骤任务的每次 `odsh.cua` / `odsh.visual` 都传入 `leaseToken`。任务间隙仍持有租约，不是单次点击锁。保守起见，文件 OCR 也受相同资源保护。
3. 思考/空闲间隙在到期前调用 `{"action":"renew","token":"<token>"}`；可传 `ttlMs` 改时长。默认 30000 毫秒，允许 150–300000 毫秒。仅实际工作期间自动续租，不为空闲持有者永久续命。
4. 结束调用 `{"action":"release","token":"<token>"}`。执行在途拒绝释放。凭证是秘密，不应记录或共享。`owner` 仅是不可信诊断标签，不是身份认证。

租约管理器使用 256 位随机凭证和单调时钟判断过期，并在执行期间续租。同一凭证并发执行也拒绝而非排队；忙时等待原调用结束再尝试。过期旧凭证不能续活、执行或释放新租约；凭证不会传给远端或驱动参数。

## 恢复与保证范围

只允许空闲且过期的持有者被替换。在途始终阻止接管；执行后失租校验不允许报告受保护成功。后端任何失败均保守隔离资源，包括可能无害的参数/OCR 错误，以可用性换安全；后端结果携带 `leaseQuarantined` 提示。隔离后本进程不再允许领取/续租/释放/执行，没有自动解锁命令；挂起执行会持续忙碌。操作员必须确认/终止旧本地子进程和远端工作后才能重启。网络超时、HTTP 响应都不是远端 fencing，也不能证明分离副作用已经停止；不能声称重启即可安全接管。

保证仅限同一已加载 Module、同一 Node 进程内的合作式受管入口。多进程、worker isolate、重复包副本、其他插件、人工桌面操作、直接 HTTP/驱动访问、任意 `odsh.exec` / `odsh.serve` 命令和注册表第三方工具都可能绕过，需独立限制权限和外部写入者。没有崩溃持久隔离、跨进程仲裁、远端 fencing、回滚、恰好一次、幂等或不可逆副作用保护。凭证不是租户认证；共享凭证即共享权限。不要让多个独立进程控制同一桌面后宣称本模式提供保护。

## 续租失败

续租失败时停止派发新的桌面步骤。凭证过期或被替换后，应先确认旧操作已经结束，再重新领取租约，并重新读取桌面状态后继续。资源已隔离时按上述操作员流程恢复。超时动作可能已产生副作用，应确认结果后再决定是否重试。
